The Challenge

Orbital dynamics is powerful
but fragmented

Critical tools for orbit estimation and prediction are generally closed-source, fragmented, or domain-specific — inaccessible to the broader scientific community.

⚡

Conflicting findings hard to resolve

Without open algorithms and data, discrepancies across studies cannot be traced or corrected by the community.

🔒

Unexpected results hard to validate

Closed platforms prevent independent verification of key results in planetary science and space safety.

🧩

Cross-domain collaboration hindered

Domain-specific tools block knowledge transfer between SSA, planetary science, and fundamental physics.

🚀

Growing urgency

Crowded near-Earth orbits, new planetary missions (JUICE, Euclid, LSST), and asteroid threat monitoring all demand open, scalable solutions now.

The GOOD Solution

i.a

Run & archive new user-defined orbital analyses with standardized, version-controlled configurations

i.b

Platform-executed analyses — no local HPC required, accessible to researchers without large compute resources

ii

Retrieve existing analyses with full reproducibility — every result traceable back to its input data and model configuration

iii

Auto-generate configurations for new analyses based on target body, accuracy requirements, and available datasets

iv

Automatic updates — archived analyses are refreshed when new data or software improvements become available

The Platform

Top-level requirements

Open by design, useful in practice

These commitments guide the platform’s development across planetary science, space situational awareness, and related applications.

01

Reproducible analyses

Package data, configurations, software versions, processing history, and outputs so analyses can be rerun and examined.

02

FAIR & interoperable

Use persistent identifiers and established standards where possible, with translation layers for external tools and formats.

03

Scalable & traceable

Support large and diverse datasets while preserving complete lineage from source data to published result.

04

Accessible & extensible

Serve users through web and terminal interfaces, open documentation, and reusable configurations that can grow with the community.

Work Packages

Four work packages,
one open platform

The GOOD platform is built through tightly coordinated development streams, each staffed by dedicated developers and supported by the co-applicant team.

WP1

Tudat Core Development

Develop a standardized configuration layer for Tudat (JSON/XML), replacing bespoke Python scripts. Implements configuration auto-generation from user inputs, and adapts Tudat's architecture for platform integration.

Configuration Layer Auto-generation C++ / Python
WP2

GOOD-WISE Core Development

Adapts WISE astronomical data-handling technology from sky surveys to solar system use. Develops data models, workflows, and databases for both spacecraft (WP2-2) and natural bodies (WP2-3) with full data lineage.

Data Lineage WISE Tech PostgreSQL
WP3-1

Near-Earth SSA

Application-focused development for Space Situational Awareness. Improves astrometry bias characterization, automates uncertainty propagation for sensor scheduling, and integrates near-Earth object tracking data.

SSA Uncertainty Prop. Debris Orbits
WP3-2

Solar System Dynamics

Large-scale astrometric analysis linking survey data (Gaia, LSST, Euclid, JWST) with orbital estimation. Extracts asteroid tracks from archival surveys and supports planetary interior and evolution science.

Astrometry Planetary Science Survey Integration
WP3-3

Spacecraft Radio Tracking

Implements mission-specific background models (atmosphere, radiation pressure, gravity variation) and automates data retrieval pipelines. Covers missions including Cassini, JUICE, Rosetta, and Mars Express.

Radio Science JUICE / PRIDE Mission Data
WP4

Dissemination & Governance

Establishes governance structure (steering committee + advisory board), community outreach, documentation, workshops, and a national symposium. Ensures long-term sustainability and community ownership.

Open Governance Community Documentation
